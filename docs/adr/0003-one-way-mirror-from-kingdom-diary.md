# 國王日記單向鏡像，新系統永遠不回寫

國王日記（`baobu_money_track`）是共同花費與欠款的唯一事實來源。新系統以 Cloud Function
監聽它的 `couples/{coupleId}/notebooks/{notebookId}/transactions/{txId}`，把交易單向複製成
新 database 裡的事件。**新系統不對國王日記做任何寫入。**

鏡像進來的事件，金額不可修改（要改回國王日記改），但可以補上帳戶與標籤。

## 為什麼

雙向同步一定會遇到「兩邊同時改同一筆」的衝突，那是個沒有正確答案、只能一直流血的問題，
而且它解決的是一個使用者根本不在乎的情境。單向、唯讀、用來源交易 id 去重的複製，
失敗就重跑，數字不會對不起來。

## Consequences

- 國王日記的程式碼**一行都不用改**。
- 鏡像必須冪等：用來源交易 id 當鍵，重跑不會產生第二筆。
- 鏡像進來的事件在收件匣裡是「待補完」而非「待確認」——它已經計入餘額（先用預設帳戶），
  使用者只是去補帳戶與標籤。
- 誰付錢給誰的語意沿用國王日記的 `payer` / `beneficiary`（值為 `baobao` / `bubu` / `both`）。
  自己幫自己出的只記在自己這邊；幫共同或幫對方出的，兩邊都會產生事件。
