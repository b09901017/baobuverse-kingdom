# 還款記成一般交易，不實作 settlement 型別

寶步之間直接給錢（還款、代墊回沖、單純把錢拿給對方），在國王日記裡就記成一筆
**普通的 `payer` / `beneficiary` 交易**，額外標上「洗錢」標籤。不使用、也不實作
`type: 'settlement'`。

## 為什麼這樣算得出來

國王日記的欠款是由「誰幫誰出了多少」累加出來的。把錢拿給對方，在帳本語意上
就等於「幫對方出了那筆金額」，因此它天然會抵銷既有欠款：

> 步幫共出 500 → 寶欠步 250
> 寶拿 250 現金給步，記成「寶幫步出 250」→ 淨額歸零 ✓

部分還款自動成立（還多少記多少，剩下的繼續掛著）。互相代墊來代墊去也自動成立
（國王日記自己算淨額）。而「隨手給對方錢」本來就該產生反向欠款，語意是對的。

## 為什麼要特別記下來

`js/utils/SettlementDetector.js` 裡有一整套為 `type === 'settlement'` 準備好的骨架，
註解寫著「🔮 未來支援」。**那是刻意不實作的，不是漏掉的。** 沒有這份紀錄，
未來的人（包含我們自己）會以為那是待辦事項而去把它做完，然後得到兩套互相打架的還款語意。

## Consequences

- 「洗錢」標籤是新系統判斷的依據：有這個標籤，就把這筆從「支出」改判成兩人帳戶之間的轉帳
  （見 ADR-0001 的分錄模型）。
- 兩邊各自選自己的帳戶。國王日記不知道錢從哪個戶頭出，所以雙方在自己的收件匣裡補。
- 保留一個「算不算欠款」的欄位，預設算。目前寶步之間沒有「送禮不算帳」的概念，
  但欄位先留著，之後要加不用改資料。
