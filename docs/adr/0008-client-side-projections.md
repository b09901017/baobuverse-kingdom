# 投影在手機端由事件算出，不用 Cloud Function 維護

ADR-0001 的核心（一次動作一則事件、append-only、其他都是投影）不變，改的只是投影在哪裡算。
兩個人一年頂多幾千則事件，手機每次讀進當期事件、當場算出餘額與日記，速度不是問題。

## 為什麼

後端投影引擎是第一版評估裡風險最高的部分：Firestore 觸發是 at-least-once，
漏做去重就會重複扣款。投影改在讀取時計算，同一份事件算幾次結果都一樣，這個問題不存在；
離線時也不會「餘額慢半拍」，因為本地快取的事件就能算。

## Consequences

- 不寫任何投影 collection，也就沒有「投影壞掉要修」的工具（國王日記的 `BalanceRepairTool`、
  `BalanceInitializer` 就是存餘額的代價）。
- 去重仍然需要，但只在**外部來源進來時**：國王日記鏡像、銀行通知、載具發票都以來源 id 去重。
- 資料量真的大到算得慢時，再加快取或期初餘額快照。快照可以隨時從事件重建，不是事實來源。
