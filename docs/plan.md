## 前提（使用者的回答）

- 兩個人都用 **Android**。
- 唯一「沒有就不想用」的功能：**自動抓銀行與 LINE Pay 通知**。
- 國王日記（`baobu_money_track`）是 Vanilla JS + Vite + Tailwind，有包 Capacitor APK，也部署在 `baobu-app.web.app`。
- 程式幾乎全交給 AI 寫，使用者負責測試與提需求。

## 技術選擇

| 項目 | 選擇 | 理由 |
|---|---|---|
| 形式 | **PWA**，不打包 APK（ADR-0007） | 唯一硬需求（抓通知）由 MacroDroid 在手機端做，前端是什麼都一樣 |
| 框架 | **React + TypeScript + Vite** | AI 寫 React 最穩、每次對話照同一套規矩；錢的邏輯需要型別保護。國王日記的 `js/core/` 手工重做了 Router、StateManager、ListenerManager，就是純 JS 寫大之後的樣子 |
| 樣式 | Tailwind | 與國王日記一致 |
| 動畫 | Motion（原 Framer Motion） | 不另外引入 GSAP，避免兩套動畫庫 |
| 後端 | Firebase Auth / Firestore（具名 database，ADR-0002）/ Cloud Functions / Hosting | 雲端函式只用在：收通知、載具排程、國王日記鏡像 |
| 投影 | **在手機端由事件算出**（ADR-0008） | 兩個人、一年幾千筆，算得很快；去掉後端投影引擎與冪等難題 |

兩個 app 是**同一網域下的兩個 PWA**（例如 `/treasury/`、`/nest/`），各自一份 manifest：
桌面上是兩個圖示、兩種節奏，但登入狀態共用。

**要先驗證**：PWA 用網頁版 Google 登入，能否登入國王日記同一個帳號（國王日記 APK 用的是原生登入外掛）。

## 功能清單與做法

| # | 功能 | 做法 | 備註 |
|---|---|---|---|
| 1 | 載具記帳 | 申請財政部電子發票 API 的 AppID／APIKey，雲端每天抓一次載具發票 → 收件匣 | **待確認**：規格書只寫「開發者或開發廠商須先經過申請程序」，個人能否申請要實際試。查詢需手機條碼驗證碼，存在雲端要加密 |
| 2 | 桌面捷徑 | manifest `shortcuts`：長按圖示出現「記支出／記收入／記轉帳」 | PWA 做不出顯示餘額的桌面小工具 |
| 3 | 拍發票 | 電子發票掃左側 QR code（含日期、金額、賣方）；傳統發票與手寫收據用 AI 看照片辨識 | AI 辨識結果一律進收件匣等確認，不直接入帳 |
| 4 | 刷卡記帳 | 銀行通知 → MacroDroid → 雲端函式 → 收件匣（spec §5.1 的模板解析） | 接收網址必須帶密鑰 |
| 5 | 金額加減 | 金額欄是小計算機，輸入 `120+45-20` | |
| 6 | 預算、存錢目標 | 從事件即時算本月花費對比預算；存錢目標看存款帳戶餘額 | 不建彙總表 |
| 7 | 連結試算表 | 先做匯出 CSV；之後做 app → Google 試算表的**單向**同步 | 不做試算表改回 app，會破壞 append-only |
| 8 | 語音 | Chrome 語音轉文字，解析「午餐 120 現金」 | 排最後 |
| 9 | 各帳戶存款 | 銀行、悠遊卡、錢包、信用卡（負債）各是一個帳戶，餘額由事件算出，定期對帳 | 核心 |
| 10 | 固定支出 | 到期產生草稿進收件匣 | app 關著時要提醒，需要 FCM 網頁推播（PWA 不能自己排程本地通知） |
| 11 | 共同花費 | **待決定**，見下方 | |

### 刷卡但沒有發票

刷卡通知本身就建立那則事件（`liab:信用卡` → `ext:商家`，支出、負債增加）。
發票只是同一則事件的附加證據，有就補上品項，沒有也完整。還卡費是 `acc:銀行` → `liab:信用卡` 的轉帳。

### 同一筆消費從好幾個來源進來（ADR-0009）

刷卡通知、載具發票、拍照、信用卡帳單 CSV 可能描述同一筆消費。
一次動作只有一則事件，其他來源是證據：先到的建立草稿，後到的若金額相同、日期相近就**建議合併**，
由使用者在收件匣確認。合併規則在第 2 階段一開始就要設計，是 #1、#3、#4、#7 背後真正的工作。

### 待決定：#11 共同花費與國王日記

國王日記本身就是情侶共同記帳（多帳本、結算）。選項：

- **A.** 國王日記繼續管共同花費，新 app 單向讀取（現行 ADR-0003）。
- **B.** 新 app 取代國王日記，國王日記退休。
- ~~C. 兩邊都記~~：同一筆錢記兩次，不做。

## 明確不做

| 不做 | 理由 |
|---|---|
| 存網銀帳密、代登入網銀抓資料（麻布記帳的「代理同步」） | 帳密外洩損失的是真錢；OTP、驗證碼、改版讓它一直壞；可能違反銀行條款。開放銀行 TSP 需公司身分與逐家簽約，個人無法申請 |
| NFC 讀悠遊卡 | 網頁 NFC 讀不了悠遊卡；需原生程式，且卡片資料受加密保護。改用：加值記轉帳、搭車記支出、偶爾對帳 |
| 打包 APK | 見 ADR-0007 |

## 素材

可以用外部素材，前提是**風格統一、授權乾淨**：

- 先定王國畫風（Impeccable 協助），主要素材只從一兩個系列挑，缺的用 AI 生成補。
- 授權乾淨的來源：Phosphor／Tabler 圖示、Microsoft Fluent Emoji、Kenney／Quaternius（CC0 遊戲素材與音效）、unDraw。LottieFiles、Rive 社群作品授權各自不同，逐一確認。
- **不用有版權的角色**（LINE 貼圖、三麗鷗、迪士尼）：國王日記的網址與 repo 是公開的，新 app 部署後同樣是公開散布。
- 圖片轉 WebP、動畫用 Lottie／Rive；核心畫面素材預先快取，大型場景素材用到才下載。
- 第 1 階段只需要圖示和一個記帳完成的小動畫。
