## 使用者的決定

- **形式**：先做 React PWA，測試沒問題再用 Capacitor 包成 APK。
  理由是使用者自己的：AI 好寫、好維護，自己測試方便。
- **自動記帳**：付完錢後通知進收件匣，**按一下確認**就入帳。不要求完全不碰。
- **共同花費**：暫時繼續由國王日記管。
  - 國王日記已經用了一兩年，資料多、也習慣了，**最怕弄壞它**。
  - 曾想過「在新 app 記、寫進國王日記」，但那要寫入國王日記，目前不做。
  - 之後可能合併：把國王日記的資料**複製**過來，國王日記照常運作當備份。
  - 國王日記本身的 bug 在它自己的 repo 修。
- **不做代登入網銀**（存網銀帳密、代登入抓資料）。
- **NFC 讀悠遊卡**：不確定有沒有必要，包成 APK 之後再研究，不是「不做」。
- **家務、物品**：先不想，先把記帳做完整。
- **Skill**：見下方「Skill」。
- **素材**：要用外部素材讓 app 更豐富，挑哪些還沒定。

## 最想要的（使用者的話）

> 我希望能做到讀取訊息然後自動記帳，也許是銀行通知、LINE Pay／其他支付軟體的通知、信用卡、悠遊卡、發票、載具等等，
> 我希望我付完錢後就可以直接記帳，並且可以很清晰地知道錢的流向，不論是帳戶之間的互轉還是各種預算花費，
> 也希望可以有紀錄固定花費，可以越用記帳越了解我自己，是一個理財小幫手。

> 我想要一個 app 就可以看到我目前所有帳戶的狀況，更有掌握感。

使用者提過的功能：載具記帳、桌面捷徑或小工具快速記帳、拍發票、刷卡記帳、金額可以加減、
預算與預計存多少、連結試算表、語音、各帳戶存款（銀行、悠遊卡、錢包現金）、固定支出、和伴侶的共同花費。

## 前提（事實）

- 兩個人都用 **Android**。
- **步**（使用者本人）主要用**金融卡與現金**，銀行有郵局、國泰、中國信託。
  **寶**（女朋友）主要用 **iCash Pay 與信用卡**。app 與功能相同，差別只在自動與手動的比例。
- 現金沒有自動來源，所以手動記一筆一定要快。
- 步記得郵局、國泰有消費通知，尚未截圖確認。寶的手機尚未確認。
- 步會從郵局轉帳到國泰或中國信託，會收到「郵局出帳」與「國泰入帳」兩則通知。
- 刷卡有時會同時收到刷卡通知和出帳通知。
- 國王日記（`b09901017/baobu_money_track`）是 Vanilla JS + Vite + Tailwind，有包 Capacitor APK，也部署在網頁。
- 程式幾乎全交給 AI 寫，使用者負責測試與提需求。

## 已討論、使用者沒有反對的理解

- 自己帳戶之間轉帳的兩則通知（出帳＋入帳）是**同一筆轉帳**，不是兩筆；跨行手續費的差額是一筆支出。
- 刷卡通知和之後的出帳通知是**同一筆消費**，後到的建議合併，不是第二筆。

## 階段（草稿，可以再調整）

依「最痛的是付完錢要自動記帳」排出來的。

| 順序 | 內容 |
|---|---|
| 1 | 帳戶總覽、**快速**記一筆、對帳（含初始餘額） |
| 2 | 自動抓通知 → 收件匣 → 按一下確認，同一筆錢的多則通知合併 |
| 3 | 錢的流向：帳戶之間的轉帳、分類花費 |
| 4 | 預算、固定花費 |
| 5 | 其他來源：發票、載具 |
| 6 | 理財小幫手 |
| 之後 | APK（桌面小工具、app 自己讀通知、研究悠遊卡 NFC）、共同花費合併、試算表、語音、窩日記、沉浸畫面 |
