# 03 預設資料：匯入一次、重置後一鍵套用

Status: done
Blocked by: 01

動工前先讀：`../spec.md`；01「做完時留下的」；`apps/treasury/src/reset.ts`、`test/reset.test.ts`；`store.ts` 的 `save`；`firestore.rules`；`.local/kingdom-accounts.md`（真實資料，**內容不寫進 repo**，指令輸出也不要印金額，見 lessons 第五條）；ADR 0001；階段 0 HANDOFF「中途發現 · 段四、段五」的重置。

## 使用者要的

「**帳戶先預設好**：AI 把帳戶問清楚，app 一開始就預設好，之後可以新增、刪減。帳戶資料使用者方便時再填，放不公開的 `.local`，不進公開 repo。」（`docs/plan.md`）
「**上線前要能一鍵重置**」（`docs/plan.md`）

## 為什麼會這樣

- repo 公開，網站的 JS 誰都下載得到，所以資料不能進程式，也不能打包進網站。
- 一鍵重置（`resetMine`）會刪帳戶、罐子、標籤。預設資料如果只跑一次，重置之後就沒了；使用者常在手機上重置，不能要求回電腦跑指令。
- 加密貨幣投入：投資帳戶不能對帳（`reconcile-investment`），各自投入用轉帳記。第一次對帳的初始餘額會吸收排在它前面的轉帳（`ledger.ts` 的 `reconcile`：`diff = actual - running`，第一次是 `opening`），所以餘額、淨資產都對。
- 共有帳戶的事件兩個人都看得到（`participantsOf`）：**投入的轉帳與步的初始餘額要分開成不同事件**，不然寶看得到步帳戶的實際餘額。

## 做法

1. 資料檔的形狀（純函式，測試用假資料）：`parsePresets(unknown)` 檢查格式、回傳清楚的錯誤（哪一列、什麼問題）。內容：帳戶（ID、名稱、種類、主人、`paidByOthers`、自己的備註、現在的餘額；信用卡是負數）、罐子、標籤（照順序）、投入（來源帳戶、目的帳戶、金額）。ID 是穩定的字串。
   要擋：只有「主人只有匯入的人」的帳戶可以有餘額與備註（別人的、共有的、投資的都不行，不然對帳事件的參與者會多出別人，對方看得到實際餘額）；共有的帳戶只能是投資（`plan.md`：目前沒有共同帳戶；非投資的共有帳戶，對帳會全算給記的人）。日常罐的 ID 要是 core 或 app 定好的那個常數（05 沒有日常時也用它建，先記一筆再套用才不會有兩個日常）。
2. 文件：`kingdoms/{k}/presets/{personId}`，規則只有本人讀寫、不能刪；規則測試。寫進 ADR 0001 的路徑表。
3. `presetChanges(presets, me, now)`（純函式）→ 給 `save` 的 `Changes` 加上要寫進 prefs 的備註與標籤順序：
   - 每一筆投入一則事件（轉帳），ID 固定；
   - 每個有餘額的帳戶一則對帳事件，ID 固定，`recordedAt` 在投入之後；參與者只有自己。不合成一則：流水頁一則一列，合在一起的話改或刪一次就動到所有帳戶的初始餘額；
   - 帳戶、罐子、標籤用固定 ID 寫入（重置後寶的帳戶還在，同 ID 會覆蓋，01 的規則要放行）。
4. 重置不刪 `presets`；`RESET_KEEPS` 加一句；`test/reset.test.ts` 的 `remaining()` 要查 `presets`，不然「重置不刪」那支會空過。上線前（`!LAUNCHED`）、沒有任何自己的帳戶、而且有 presets 時，畫面（04）出現「套用預設」；匯入也只有上線前有（跟重置一樣上線後不出現，寫進 HANDOFF「上線那天要做的」）。
5. 匯入的畫面在 04（設定頁選檔）。這一支做函式與測試。
6. 從 `.local/kingdom-accounts.md` 產生 `.local/kingdom-presets.json`（`git check-ignore` 確認不進版控；指令不印金額）。段裡只產生檔，不匯入正式資料。

## 判準

- 重置後按套用，每個自己的帳戶餘額是不是檔案寫的那個數字？共有帳戶的步、寶投入是不是各自那個數字？（測試用假數字）
- 步的淨資產是不是「自己帳戶加起來＋自己投入的」？寶投入的會算進步的嗎？步的帳本裡寶的帳戶負的那段會進步的淨資產嗎？
- 每一則初始餘額的參與者是不是只有步？投入的事件裡看得到步帳戶的實際餘額嗎？檔案裡寶的帳戶或共有帳戶寫了餘額，會擋下來嗎？
- 投入的轉帳算支出嗎？（我用的、我付的、收入都要是 0；README 第一條）
- 第一次對帳的差額會被算成對帳差額嗎？（應該是 0 筆差額）
- 連按兩次套用、兩台裝置都按，會變兩倍嗎？（ID 固定：第二次 `recordedAt` 不同，規則整批拒絕、什麼都沒寫；`written` 的錯誤要接住，給白話的說明）
- 寶讀得到步的 `presets` 嗎？重置會刪掉 `presets` 嗎？
- 檔案格式錯（少欄位、金額不是整數、投資帳戶有餘額、主人沒有人、轉帳兩邊不同人）會擋下來、什麼都不寫嗎？
- `git grep` 真實金額與 `.local` 裡獨有的標籤名（`docs/plan.md` 或 `spec.md` 原話已經有的那幾個不算）：repo 裡有嗎？（用 spawnSync 在程式裡比、只印筆數，lessons 第五條）

**補定的**（issue 沒寫，照之前說的判斷）

| 情況 | 決定 | 理由 |
|---|---|---|
| 事件的日期 | 檔案的 `asOf`（填數字的那天），`recordedAt` 才用 `now` | 那些數字就是那天的。晚幾天才套用時，之後補記那幾天的支出會正確地扣掉；卡片的「N 天沒對帳」也是真的。`asOf` 當天補記的支出排在初始餘額之後（初始餘額沒寫時間） |
| 事件的 ID | 投入 `preset-transfer-{第幾筆}`，初始餘額 `preset-opening-{帳戶 ID}` | issue 要固定；不用在檔案多寫一欄 |
| 事件的名稱 | 投入「投入」、對帳「初始餘額」 | 流水頁（05、06）才有字可以顯示 |
| 幣別 | 檔案不用寫，寫進帳戶文件時補 `TWD` | 現在只有台幣 |
| 不認得的欄位 | 擋下來 | 打錯字（`balence`）不會被默默丟掉、餘額就不見了 |
| 信用卡的餘額寫成正的 | 擋下來 | issue 說信用卡是負數；寫反的話欠款變存款，淨資產差兩倍 |
| 標籤帶 `defaultJar` | 擋下來 | 使用者說預設的標籤都不帶 |
| 檔案沒有備註 | prefs 不寫 `accountNotes` 這一格 | merge 時空的 map 會把原本的備註蓋掉（測試先紅過） |
| `.local/kingdom-presets.json` 怎麼產生 | `.local/make-kingdom-presets.mjs`（`node .local/make-kingdom-presets.mjs`，只印筆數） | 裡面有真實名稱的 ID 對照，所以放 `.local`。改了 `kingdom-accounts.md` 重跑就好 |
