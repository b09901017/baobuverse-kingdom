# 02 core：退款註記查得到、改刪不會讓退款失效、存得進去的帳本一定算

Status: done
Blocked by: 無

動工前先讀：`../spec.md`；GLOSSARY「退款」；`packages/core/src/validate.ts`（`refund` 那段、`findItem`、`refundedBefore`）；`packages/core/src/ledger.ts`（`refund`、`refundProblems`、`byTime`）；`packages/core/src/book.items.test.ts` 的退款；階段 0 HANDOFF「中途發現 · 段三」第二條。

## 使用者要的

「**退款**：在原來那筆上作註記。」（`docs/plan.md`）
階段表：「退款註記」。流水頁可以改、可以刪是這一輪主控定的（`../spec.md`）。

## 為什麼會這樣

- 退款是一則新事件、指到原本那一項（ADR 0001 第 1 點）；註記要從事件找，core 現在沒有公開的查法（`refundedBefore` 是內部的，也只回傳加總）。
- `validateEvent` 只在存退款時對照原本那項；**反過來存原本那筆時不看退款**。把金額改到比已退的少、把品項拿掉、把日期改到退款之後、把那則刪掉，都存得進去，然後帳本的 `refundProblems` 把退款整則丟進 `problems`，數字默默變了。
- `byTime` 排序時「沒寫時間的排前面」。原本那筆有時間、同一天的退款沒寫時間（或時間比較早）時，退款排在原本那筆前面：`validateEvent` 用 `findItem` 找得到、存得進去，帳本卻 `spent.get` 不到、算 `refund-target`。**存得進去卻不算**。

## 做法

照 `tdd`，一條規則一支測試、先紅後綠。

1. 公開 `refundsOf(events, ref)`（只算已確認的）：回傳每一筆退款的事件 ID、日期、金額；品項的 `refundedAmount` 可以從它加。不改 `Line`（`../spec.md`）。
2. `validateEvent(event, catalog, events)`（給了 events 才檢查）：
   - 存退款：照 `byTime` 的先後，退款要在原本那筆之後，不然 `refund-target`。先後的比較共用 `byTime`（`ledger.ts` 已經 import `validate.ts`，要搬位置的話注意循環）。
   - 存退款：退回的帳戶要是原本那筆誰出的人的（新的 `ProblemCode`）。01 開放帳戶之後 `unknown-ref` 不再擋：步付 1,000、退到寶的帳戶，現在存得進去，步的淨資產少 1,000、寶的多 1,000。
   - 同一則事件裡好幾筆退款指到同一項：加起來不能超過還沒退的（現在是一筆一筆比，60＋60 對 100 存得進去、帳本不算）。
   - 存支出：如果這一則（同 ID）已經被退款：被退的品項要還在、金額不能比已退的少、時間不能晚於最早的那筆退款、誰出與幫誰不能改；不然新的 `ProblemCode`（例如 `refunded-item-changed`）。
     誰出、幫誰也要擋，是因為退款文件的參與者是存退款時算的：幫步改成幫共之後，寶看不到那筆退款，寶的我用的會多算（要改就先刪退款）。
3. 公開一個問「這則能不能刪」的函式（例如 `blockersOfDelete(eventId, events)`，回傳擋著的退款）。畫面照它把刪除按鈕換成說明。
4. 註解、`ProblemCode` 的說明寫白話；`index.ts` 匯出。

## 判準

- 原本那筆 14:00、同一天退款沒寫時間：存得進去嗎？（應該被擋，不是存進去之後不算）
- 原本那筆 1,000 已退 300：改成 200 存得進去嗎？改成 300 呢？（前者擋、後者可以）
- 原本那筆 10/20、10/25 退款：改成 10/26 存得進去嗎？改成 10/25 同一天但時間更晚呢？
- 把已退的品項換成新 ID（等於拿掉）存得進去嗎？
- 有退款的那筆，幫步改成幫共、誰出步改成寶，存得進去嗎？（應該擋）改名稱、罐子、標籤呢？（可以）
- 步付的那筆，退到寶的帳戶存得進去嗎？（應該擋）退到步的另一個帳戶呢？（可以）
- 同一則裡退 60＋60，那項只剩 100 可退：存得進去嗎？（應該擋）
- 有退款的那則能刪嗎？退款先刪掉之後呢？
- 退款改金額時，`refund-too-big` 會不會把自己算進去？（`refundedBefore` 有 `except`，加測試鎖住）
- 這些檢查有沒有影響 `checkForBook`（帳本讀的時候）？已經存進去的舊資料還是算，不會因為新檢查讓帳本丟掉事件。
- `refundsOf` 把收件匣（`pending`）或別項的退款算進來嗎？

## 做完時留下的

2026-10-31 段一。測試在 `packages/core/src/validate.refunds.test.ts`。

**給 05、06 用的介面（`@baobu/core`）**

| 東西 | 做什麼 |
|---|---|
| `refundsOf(events, ref)` | 這一項被退了哪幾筆：`RefundRecord[]`（`event`、`entry`、`date`、`time?`、`amount`），照時間排，只算已確認的。已退多少就是把金額加起來；註記用它 |
| `blockersOfDelete(eventId, events)` | 擋著這則不能刪的退款（`RefundRecord[]`），空的才可以刪；畫面照它把刪除按鈕換成說明 |
| `validateEvent(event, catalog, events)` | 要給 `events` 才檢查下面這些（`store.ts` 的 `save` 本來就有給）。`events` 裡有這一則的舊版也沒關係 |

**新的 `ProblemCode`（05 換成白話時要寫到）**

| 代碼 | 什麼時候 | 白話可以這樣說 |
|---|---|---|
| `refund-account` | 退回的帳戶不是原本那筆誰出的人的；或是投資帳戶；或是別筆的寶媽卡 | 這筆錢不能退到這個帳戶 |
| `refunded-item-changed` | 這筆已經有退款，這樣改會讓退款失效。**整則的**（沒有 `entry`）：排到退款之後、改回收件匣；**整筆的**（有 `entry`、沒有 `item`）：誰出或幫誰變了；**某一項的**（有 `item`）：被退的品項不見、金額比已退的少、改成直接給錢 | 這筆已經有退款，要改這裡先刪退款 |

`refund-target` 多了兩種情況：退款排在原本那筆之前（包括同一天、退款沒寫時間，因為沒寫時間的排前面；06 的表單要提醒）、退款指到自己這一則。

**判準的結果**

| 判準 | 結果 |
|---|---|
| 原本那筆 14:00、同一天退款沒寫時間 | 擋（`refund-target`）；同一天 13:00 也擋、15:00 可以，帳本算得到 |
| 1,000 已退 300：改 200、改 300 | 200 擋、300 可以；好幾筆退款加起來算 |
| 10/20、10/25 退款：改 10/26、改 10/25 更晚 | 都擋；退款有寫時間的話，同一天比它早可以 |
| 已退的品項換新 ID | 擋；沒被退的品項可以拿掉；連那一筆的 ID 換掉也擋 |
| 幫步改幫共、誰出步改寶 | 都擋；改名稱、罐子、標籤、帳戶（同一個人的）、備註可以 |
| 步付的退到寶的帳戶、退到步的另一個帳戶 | 前者擋、後者可以 |
| 同一則 60＋60，只剩 100 | 擋；60＋40 可以 |
| 有退款的那則能刪嗎？退款先刪掉呢？ | `blockersOfDelete` 回傳擋著的退款；先刪退款之後是空的 |
| 退款改金額會不會把自己算進去 | 不會（100 對 100 可以、101 擋） |
| 影響 `checkForBook` 嗎 | 不會：退到別人的帳戶、投資帳戶、別筆寶媽卡、誰出幫誰被改過的舊資料，帳本照算、不進 `problems` |
| `refundsOf` 算進收件匣、別項的嗎 | 不會 |

**被擋的理由是真的**：測試裡同時驗了「真的存進去，帳本的 `problems` 就會有那一則」（金額改少、排到後面、品項拿掉、指到自己、60＋60）。

**比 issue 多做的**（都是「存得進去卻算錯」的同一類，一兩行）：

- 退回的帳戶也擋**投資帳戶**（GLOSSARY：進出都是轉帳）和**別筆的寶媽卡**（銀行付的那筆退進寶媽卡：寶媽卡的餘額變少，還欠的清單卻沒變，兩個數字對不上）。刷寶媽卡的那筆退到寶自己的帳戶可以（寶拿到錢、還是欠寶媽，數字是對的）。06 的清單也要排除別筆的寶媽卡。
- 有退款的那筆也不能**改回收件匣**、被退的那一項不能**改成直接給錢**（帳本都會丟掉退款）。
- **比的是實際幫的人**，不是欄位：品項寫明幫步、整筆也是幫步不算改；比例的順序、從 Firestore 讀回來的欄位順序不同也不算改。比例 6:4 改成 3:2 算改（擋，比較保守）。

**搬了什麼**：`byTime` 從 `ledger.ts` 搬到 `dates.ts`（`ledger.ts` 已經 import `validate.ts`，放那裡會循環）。沒有從 `index.ts` 匯出；05 的流水頁要照同樣的先後排的話再匯出。

**故意弄壞看會不會紅（lessons 第十條）**：17 種弄壞法，16 種第一次就紅；「退款可以指到自己這一則」紅 0 支（舊版與新版同一天時，先後的比較也會擋掉），補了「順便把日期改晚」之後紅 1 支。
