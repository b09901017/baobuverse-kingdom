# 階段 0 地基

這一輪把國庫（`apps/treasury`）的地基蓋好：新的 Firebase 專案、monorepo 骨架、`packages/core` 的資料形狀與算錢規則、
Google 登入與存讀、部署到一個網址、上線前一鍵重置。**畫面只做到能驗證地基**，真正的記帳畫面是階段 1。

決定都在 `docs/plan.md`（「使用者的決定」與「已討論、使用者沒有反對的理解」）與 `GLOSSARY.md`，這裡不重寫，只指出這一輪用到哪幾條。

## 策略

1. **先把錢算對，再接雲端**：`packages/core` 是純 TypeScript、不碰 Firebase，所有算錢規則在這裡、用 Vitest 測。app 只負責存讀與畫面。
2. **雲端的每一步都寫死目標**：新專案 ID 寫進 `.firebaserc`；部署腳本拒絕在目標不是新專案時執行；`firebase.json` 只列新專案的網址與資料庫。
3. **一個薄薄的端到端路徑**：登入 → 用 core 建一則事件 → 存進 Firestore → 讀回來 → 用 core 算出餘額 → 顯示。階段 1 在這條路上長畫面。

## 風險

| 風險 | 怎麼防 |
|---|---|
| 部署或規則蓋到國王日記（`baobu-app` 的預設網址與資料庫） | 新專案獨立；部署腳本檢查專案 ID；06 的判準 |
| 資料形狀之後要大改（已經存了資料） | 03 用設計兩次＋ADR；上線前可以一鍵重置，形狀改了就重置 |
| 金額用浮點數算錯 | core 只用整數元（外幣之後再說，形狀留幣別） |
| 兩個人共用資料（階段 6）的權限設計卡住 | 03 的形狀先想好「寶也記、兩人都看得到」怎麼放，05 的規則先只開給自己 |

## 不做（之後的階段）

記帳畫面、卡片牆、對帳畫面（階段 1）；標籤三幫手、語音、APK（階段 2）；寶的帳號與共用畫面（階段 6）。
