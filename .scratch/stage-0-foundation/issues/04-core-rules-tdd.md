## 要有測試的規則（從步的角度；罐子看「我用的」）

| 情況 | 我付的 | 我用的 | 往來帳（寶欠步） | 其他 |
|---|---|---|---|---|
| 步幫自己付 5,000 | 5,000 | 5,000 | 0 | |
| 步幫寶付 3,000 | 3,000 | 0 | +3,000 | 寶的我用的 +3,000 |
| 寶幫步付 1,200 | 0 | 1,200 | −1,200 | |
| 步幫共付 2,000（5:5） | 2,000 | 1,000 | +1,000 | 寶的我用的 +1,000 |
| 寶幫共付 2,000（5:5） | 0 | 1,000 | −1,000 | |
| 步寵寶 500（進階：不用還） | 500 | 0 | 0 | 寶的我用的 +500；步的寵對方 500 |
| 寶寵步 300（買東西） | 0 | 300 | 0 | 步的被寵 300 |
| 寶直接給步 1,000 寵步 | 0 | 0 | 0 | 步的收入 1,000、被寵 1,000 |
| 寶還步 5,000 | 0 | 0 | −5,000 | 不是收入；步的帳戶 +5,000 |
| 郵局轉國泰 10,000 | 0 | 0 | 0 | 兩個帳戶一減一加，淨資產不變 |

再加：

- 恆等式：我付的 − 我用的 ＝ 往來帳因支出的變化（寶欠步為正；還款不算）＋ 寵對方 − 被寵（買東西的）＋ 待收的增加 − 寶媽卡幫出。
  上表每一列各驗一次（第「寶還步」列因支出的變化是 0），寶媽卡、待收的例子也各驗一次；按月攤只在整段攤完的期間成立，單月不驗。
- 刷信用卡 1,000：信用卡欠款 +1,000；用銀行繳卡費 1,000 是轉帳。跨行轉帳 1,000＋手續費 15：同一則事件，轉帳 1,000＋支出 15。
- **寶媽卡**（寶的角度）：刷 3,000 冥想 → 寶的冥想罐（我用的）3,000、寶的我付的 0、寶媽卡還欠 +3,000、寶的淨資產不動。
  寶還寶媽 2,000（還款）→ 寶的銀行 −2,000、寶媽卡還欠 1,000、不算支出也不算收入、寶的淨資產 −2,000。寶媽卡不算進淨資產。
- **還款先抵最早的**：10/1 寶媽卡冥想 3,000、10/15 寶媽卡日常 1,000、10/20 還 2,000 → 冥想已還 2,000、還欠 1,000，日常還欠 1,000；
  11/5 再還 2,000 → 兩筆都還清。進階手動指定：10/20 那 2,000 指定抵日常 → 日常還清、冥想還欠 2,000（多出的 1,000 再抵最早的）。往來帳用同一套。
- **待收**：聚餐 2,000、4 人平分 → 步的我用的 500、我付的 2,000、待收 1,500；朋友還 500 → 待收 1,000。1,000 元 3 人平分 → 333、333、步 334。
- **按月攤**：10/10 刷 12,000 分 12 期 → 信用卡欠款當天 +12,000；我用的 10 月到隔年 9 月每月 1,000。年繳保險 12,000 一樣。
- **投資**：步從郵局轉 10,000 進共有的加密貨幣帳戶 → 郵局 −10,000、步投入 +10,000，不是支出，步的淨資產不變。
- **對帳**：實際 1,050、算出 1,200 → 對帳差額 −150，不算支出也不算收入；之後的餘額是 1,050。第一次對帳就是初始餘額。
- **退款**：原本那一項（日常、標籤「家樂福」）820 退 95 → 日常與「家樂福」的我用的各少 95，不算收入。
- **品項**：整筆 820、標籤「家樂福」，品項 95（吃吃）＋725（居家）→「家樂福」820、「吃吃」95、「居家」725；品項加總不等於整筆時拒絕。
- **進階**：820 裡 650 那一項改成幫寶付 → 步的我用的 170、往來帳 +650；步幫共付 1,000 用 6:4（步 6）→ 步的我用的 600、往來帳 +400。
- **視角**：同一個罐子的我用的，可以依誰出、帳戶、要不要還、標籤、固定花費、分期拆開，拆開的加起來等於總數。
- **篩選**：十月與十一月各一筆日常 100，查十月的日常 → 100；查標籤「家樂福」只算有那個標籤的品項。

### 實作放哪

`book.ts` 只放介面與查詢（篩選、視角、還了沒照 `to` 拆）；事件展開成一行一行在 `ledger.ts`；要還的錢（先抵最早、往來帳互抵、退款變少）在 `debts.ts`；

### 跟 03 的介面不合、改了或補定的

**公開的型別與函式簽名沒有改**（`model.ts` 一行沒動；`book.ts`、`validate.ts` 的型別照舊）。下面是 03 沒寫到、寫規則時要定的，都只在 core 裡，資料不用動：

| 哪裡 | 怎麼定 | 為什麼 |
|---|---|---|
| 比例（`Weight.weight`） | 要是**正整數**，不然 `weights-invalid`（`ProblemCode` 的註解改了） | 金額不准用浮點數：份數是整數，`捨去(金額 × 份數 ÷ 總份數)` 才全程是整數；6:4、55:45 都寫得出來 |
| `splitEvenly` | 金額不是 0 以上的整數、人數不是正整數 → 丟 `RangeError` | 03 只寫了正常的情況 |
| `openBook` 的檢查 | 比 `validateEvent` 寬：看不到的參考資料（寶的帳本裡步的帳戶）不算問題；手動指定的還款指錯了就當成沒指定、照「先抵最早」算 | 存之前已經用 `validateEvent` 擋過；帳本裡把一筆真的還款整則丟掉，往來帳反而會錯 |
| 共有帳戶那一邊算誰的 | 轉帳另一邊帳戶的主人；另一邊看不到（寶的帳本裡步的郵局）或也是共有的，算**記的人** | 寶的帳本也要算得出步投入多少；記的人一定看得到自己用的帳戶（`validateEvent` 要求），所以是對的人 |
| 退款的行 | 指到退款那一則（`event`、`entry` 是退款的，沒有 `item`）；罐子、標籤、誰出、帳戶照原本那一項；`amortized` 照原本那一項（但不攤） | `Line.item` 是「這一筆裡的第幾項」，退款那一筆沒有品項；退款那天的日記查得到它 |
| 退款的順序 | 原本那一項要排在退款之前，不然 `refund-target`；指到直接給錢的那一項也是 `refund-target` | 帳本照時間算，退款要找得到已經算過的那一項；直接給錢不是商家的錢 |
| 還了沒（`settled`） | 只有我用的那幾行有：自己付的、不用還的是 `none`；別人先出的（往來帳、寶媽卡）照那一筆要還的錢到 `to` 那天抵掉多少，依時間先後拆成 `repaid`、`outstanding`；退款（負的）算 `outstanding` | 「寶的冥想 3,000、還 2,000 → 已還 2,000、還欠 1,000」要一行拆成兩行，拆開的加起來才等於總數 |
| 寶媽卡刷共付的那一項 | 還寶媽先算寶自己那一份還了；步那一份看往來帳（步欠寶） | 少見；照「誰出照樣記寶」的定義 |
| 分到 0 元的人 | 不列（沒有 0 元的行、也沒有 0 元要還的錢） | 1 元共付時寶分到 0 |
| `income-account`、`repayment-parties` | 也用在直接給錢收錢的帳戶不是收的人的、還款寫的帳戶不是那個人的 | 不用多開新的代碼 |

下面一條（或一組 `it.each`）一支測試，名稱用 GLOSSARY 的詞。「步的」＝ `person: 步`。

- **上表每一列**：步的 `total({ measure: "paid" })`、`"use"`、`"tab"`；「其他」欄用寶的 `use`、`spoilGiven`、`spoilReceived`（`where: { cause: "spend" | "giveMoney" }` 分買東西、直接給錢）、`income`、`balance`、`netWorth`。
- **恆等式**，上表每一列、寶媽卡、待收各一支：
  `paid − use ＝ tab ＋ spoilGiven − spoilReceived ＋ receivable − 寶媽卡幫出`；
  tab、receivable、寶媽卡幫出都不含還款那幾行（`cause: "repayment"`），spoilReceived 不含直接給錢那幾行（`cause: "giveMoney"`），
  寶媽卡幫出 ＝ −（寶媽卡的 `balance`，因為餘額那幾行是負的）。按月攤單月不驗。
- **信用卡、轉帳**：刷 1,000 → 信用卡 `balance` −1,000、步的 paid +1,000；用銀行繳卡費是轉帳（兩邊一減一加、`netWorth` 不變、paid／use 不動）；跨行轉帳＋手續費同一則事件 → 只有 15 進 paid、use。
- **寶媽卡**（寶的）：照上面表格下的例子；另外驗寶媽卡的 `balance` 是 −3,000 → −1,000，寶的 `netWorth` 刷的時候不動、還的時候 −2,000。
