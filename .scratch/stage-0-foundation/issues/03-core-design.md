## 要裝得下的（全部出自 plan.md／GLOSSARY.md，這一支不新增規則）

- **事件**：一次動作一則；誰的（擁有者）、誰記的、時間；上面掛效果（這一輪只有「錢」的效果，形狀要留給物品、日記的效果）。
- **帳戶**：屬於一個人或兩人共有（共有的投資帳戶）；種類（銀行、現金、儲值、信用卡、投資）；名稱、備註、自己的排序；幣別（現在只有台幣，形狀要留）；
  是否算進淨資產（寶媽卡不算）；信用卡與寶媽卡的餘額是欠的；投資帳戶記各人投入多少。
- **錢的種類**：支出、收入、轉帳（同一個人或共有的帳戶之間）、還款（把別人幫自己出、要還的錢還回去：步寶之間、寶媽卡、朋友）、對帳差額；
  退款是沖回原本那一項，原筆上註記。
- **一筆＝整筆＋品項**：整筆有時間、帳戶、誰出、幫誰（預設）、整筆的標籤；品項有名稱、金額、罐子、標籤；品項加起來等於整筆；
  整筆的標籤套到每一項；進階：某一項自己的幫誰、比例（預設 5:5）、不用還（寵）、有人要還我（待收，一鍵平分）、按月攤（分期、年繳）。
- **誰出、幫誰**：誰出（步／寶）、幫誰（步／寶／共）；預設要還；誰記都可以，一筆只記一次。
  寶刷寶媽卡：誰出記寶、帳戶選寶媽卡，就知道錢其實是寶媽出的（算寶的我用的、不算寶的我付的）。寶媽、朋友不是要記的「人」。
- **還款不綁品項**：先抵最早還沒還清的，進階可以手動指定；要能算出每一筆「已還多少、還欠多少」。
- **算得出來的**（定義以 GLOSSARY 為準，2026-10-30 收過好幾輪）：每個帳戶的餘額、淨資產、往來帳、寶媽卡還欠、待收；
  一段時間的**我用的**（看幫誰；罐子、標籤統計都用它）、**我付的**（看誰出）；每個數字都能依誰出、帳戶、要不要還、罐子、標籤、固定花費、分期拆開（視角）；
  對帳差額的累計。**不要**做「我負擔的」或「罐子扣＝我用的＋寵對方」（作廢）。
- **金額**：整數元。

## 過目補的：形狀要留位子，但這一輪不一定做（主控 2026-10-30 對過）

- **人**和登入帳號分開：寶還沒有帳號時，步也會幫寶記；國王日記的資料要搬過來。所以要有「人」的 ID（不等於 Firebase 的 uid），
  事件上要能標「參與者」（誰看得到），不只一個擁有者。還款動到兩人的帳戶與往來帳；寵對方直接給錢動到兩人的帳戶（往來帳不動）；幫共付動到往來帳（帳戶只動出錢的人）。
- **罐子、標籤是自己的資料**：有 ID、排序（可拖曳）、屬於誰、標籤可以帶預設罐子、改名與合併重複的（「7-11／711」）。不要只存字串。
- **金額**：用「最小單位的整數＋幣別」（台幣就是元）；轉帳要能有出、入兩個金額（換匯）；跨行手續費是「轉帳＋支出」在同一則事件。
- **事件的來源與狀態**：手動、語音、通知、固定花費；「待確認」（收件匣）；通知的外部 ID（合併同一筆的多則通知）；「有疑問」標記。
- **固定花費的範本**（名稱、大約金額、每月幾號、帳戶、標籤）。
- 帳戶不用刪、用**封存**（舊的事件還指著它）。
- **退款指到原本那一項**（品項），不只指到那一筆。

## 做法

1. 照 `codebase-design` 的「設計兩次」：至少兩個差很多的介面草案（例如「事件存原始資料、全部用查詢算」vs「存事件時順便更新彙總」），
   比較深度、測試好不好寫、窩日記好不好接、兩個人共用（階段 6）好不好放權限，選一個。
   使用者要「每個數字都能用各種角度拆開看」（視角），只存事先算好的總數做不到，比較時要把這點算進去。
2. 寫 ADR `docs/adr/0001-<slug>.md`：事件與效果的形狀、為什麼選這個（ADR 的三個條件都成立：資料存了就難改、沒前因後果會奇怪、真的有取捨）。
3. 在 `packages/core` 寫出型別與公開函式的簽名，函式本體先丟「還沒做」；列出 04 要寫的測試清單（放在 04 的 issue 底下「Comments」）。
4. Firestore 上怎麼放（集合路徑、一則事件一份文件還是拆開）也在這裡定，寫進 ADR；05 照做。要能容納：寶也記、兩人都看得到共同的、「幫自己付」對方看不到。
5. GLOSSARY 缺的詞或定義寫不準的，補 GLOSSARY（只寫名詞，不寫實作）；**改到定義就在 HANDOFF「要使用者決定的」記一筆，不要自己定**。
   注意：「支出」只是一筆錢的種類，不是統計數字；統計是「我用的」（看幫誰）與「我付的」（看誰出）。

## 判準

- 「轉帳」會不會讓任何一種看法（我付的、我用的、罐子）算成花費？
- 「幫對方付」會不會被算進自己的罐子？（不應該，算在對方的）刷寶媽卡、被寵的冥想，會不會從寶的冥想罐漏掉？（不應該漏）
- 一筆有兩個品項、整筆有標籤「家樂福」時，統計「家樂福」會不會少算或重算？
- 窩日記要列「某一天所有事件」時，需不需要讀國庫特有的東西才拿得到？（不應該需要）
- 寶搬過來後，一筆「寶幫共付、步記的」放在哪、誰讀得到？「步幫步付」寶讀不讀得到？（不應該讀得到）——答案寫成 05 的規則測試案例。
- 寶還沒有帳號時，步記的「寶幫步付」存得進去嗎？寶之後有帳號了，認得出是寶的嗎？
- `packages/core` 有沒有 import Firebase？（必須沒有）
